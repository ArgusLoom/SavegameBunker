<objective>
Gap G-02-6 (major, UAT test 6): the restore picker's per-row delete confirmation renders inside
MainWindow's `RootDialogHost`, underneath the modal `RestorePickerWindow`, so a real user can neither
see nor click it while the picker is open. Root cause (02-UAT.md, confirmed by Plan 02-10's real-click
check): `App.xaml.cs` creates the app's only `ContentDialogService`, bound to MainWindow's host, and
`DialogService.ShowRestorePickerDialog` passes that same MainWindow-scoped `DialogService` (`this`)
into `RestorePickerViewModel`, whose `DeleteArchiveAsync` calls `Confirm` on it.

Fix (the diagnosed direction): the picker window gets its own `ContentDialogHost`, and
`ShowRestorePickerDialog` builds a second `ContentDialogService` bound to that host plus a second
`DialogService` owned by the picker window, and hands that one to the view model. Then prove it in the
running app with real mouse clicks — UI Automation's InvokePattern gave a false pass in Plan 02-10 and
is not acceptable evidence here.

Purpose: closes the last open defect from ITEM-11's "not yet verified" sub-check, and the
`.planning/STATE.md` Blocker it produced.
Output: a dialog host in the picker XAML, a parameterless picker constructor, the picker-scoped
service in DialogService, a CHANGELOG Fixed entry. Two commits.

Out of scope (noticed while planning, not part of G-02-6): `AboutDialogViewModel` raises
`Error`/`Info` through the MainWindow-scoped service while the modal About window is open, so those
land behind it too. It is fire-and-forget (no blocked caller); report it, do not fix it here.
</objective>
